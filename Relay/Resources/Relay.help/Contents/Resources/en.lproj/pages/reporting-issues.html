Relay Help › Troubleshooting

Report an issue

Where to report

You can report issues in two ways:

  • File an issue on GitHub at github.com/subpop/Relay/issues
  • Message the maintainers in #relayapp:matrix.org

What to include

A good bug report includes:

  • A clear description of what happened and what you expected
  • Steps to reproduce the issue
  • Your homeserver hostname (e.g., matrix.example.org)
  • Whether other Matrix clients (Element X, Element Web) show the same behavior
  • A unified-log capture of the relevant subsystem while reproducing the issue (see below)

Capture logs

Relay logs to unified logging: subsystem app.subpop.Relay for the app, subsystem app.subpop.MatrixKit for sync, crypto, and protocol traffic. While reproducing the issue, run in Terminal:

log stream --predicate 'subsystem == "app.subpop.Relay" OR subsystem == "app.subpop.MatrixKit"' --level debug > relay-trace.log

Stop with ⌃C once you've reproduced it, then attach relay-trace.log. Narrow to one subsystem (or add AND category == "Call", for example) when the file gets large. Console.app shows the same logs with search and level filters. For an at-a-glance overview of connection state, sync mode, session trust, and server capabilities, open the Activity window (Window menu, or ⌥⌘A).

Predicate examples

Use log stream for live events and log show --last 10m for recent history. Predicates filter inside log itself, so prefer them over piping to grep. Message text is matched with composedMessage ([c] makes CONTAINS case-insensitive).

  • Ongoing HTTP traffic only: 
    log stream --predicate 'subsystem == "app.subpop.MatrixKit" AND category == "Transport"' --level debug
  • A certain error (case-insensitive): 
    log stream --predicate '(subsystem == "app.subpop.Relay" OR subsystem == "app.subpop.MatrixKit") AND composedMessage CONTAINS[c] "HTTPClientError"' --level debug
  • Errors only: 
    log stream --predicate '(subsystem == "app.subpop.Relay" OR subsystem == "app.subpop.MatrixKit") AND logType == "error"' --level debug
  • Recent history instead of live (show uses --debug, not --level): 
    log show --last 10m --predicate 'subsystem == "app.subpop.MatrixKit" AND category == "Transport"' --debug

Privacy considerations

The log capture contains room IDs, device IDs, and your homeserver hostname. It does not contain message content, encryption keys, or authentication tokens. If you prefer not to share this information publicly, contact the maintainers privately in the Matrix room.

Tip: The more specific your bug report, the faster it can be diagnosed. "Calls don't work" is harder to investigate than "Audio calls connect but no sound is heard when calling from @user:example.org to @other:matrix.org."
